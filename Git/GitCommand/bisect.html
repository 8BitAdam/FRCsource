Git Bisect

Command: git bisect · Topic: Finding regressions · Level: Intermediate

Introduction

git bisect helps you find the specific commit that introduced a bug by performing a binary search across your commit history. You mark a known "good" commit and a known "bad" commit, and Git checks out midpoints so you can test and mark them until the bad commit is isolated.

Use git bisect when you have a regression and need to quickly pinpoint the commit that introduced it.

Syntax

git bisect start
git bisect bad 
git bisect good 
git bisect run 
git bisect reset

You can also mark commits manually during the bisect process with git bisect good and git bisect bad.

Basic Use

Start a bisect session by telling Git which commit is bad and which is good. Then test the checked-out commit and mark it. 

# start bisect
git bisect start
# mark current (HEAD) or specific commit as bad
git bisect bad
# mark a known good commit
git bisect good v1.2.0
# test and mark as good or bad until bisect finishes
git bisect reset

Examples

Interactive bisect

git bisect start
git bisect bad
git bisect good v1.2.0
# run tests / manual check
git bisect bad  # or git bisect good
git bisect reset

This walks you through manual testing of each midpoint until the first bad commit is found.

Automated bisect with a script

git bisect start
git bisect bad
git bisect good v1.2.0
git bisect run ./run-tests.sh
git bisect reset

If run-tests.sh exits 0 for good and non-zero for bad, Git will automatically progress the bisect.

Common Options

  • git bisect visualize — shows the bisect state in a visual log.
  • git bisect skip — skip the current commit if the test can't determine good/bad.
git bisect skip
git bisect visualize

Troubleshooting

Bisect ends without finding a single bad commit

Ensure your good and bad commits are correctly specified and that the bug is reproducible in the checked-out commit.

Tests are flaky

Flaky tests can confuse automated bisect. Consider using manual checks or improving test reliability before running.

Practice

Try bisecting on a repository with a known regression. Create a small script that detects the bug and use git bisect run. 

git bisect start
git bisect bad
git bisect good v1.0.0
git bisect run ./test-bug.sh
git bisect reset
