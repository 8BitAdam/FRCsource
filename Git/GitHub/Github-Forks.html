Intro to GitHub Forks

Topic: Forking repositories · Level: Beginner

Introduction

A fork is a copy of someone else’s repository under your own GitHub account. It gives you a separate place to experiment, make changes, and propose updates back to the original project.

Forks are commonly used when you want to contribute to a project without direct write access.

What is a Fork?

A fork creates a full copy of a repository on GitHub. That copy is linked to the original project, which makes it easier to sync changes and submit pull requests.

Why Use Forks?

Safe experimentation

You can test ideas in your own copy without affecting the original repository.

Open-source contributions

Forks are the normal starting point for contributing to many public projects.

Personal customization

You can maintain your own version of a project and keep it separate from the original.

Basic Workflow

  1. Fork the repository on GitHub.
  2. Clone your fork to your computer.
  3. Create a branch for your changes.
  4. Commit and push your work to your fork.
  5. Open a pull request to the original repository.

Examples

Clone your fork

git clone https://github.com/your-username/project-name.git

Set the original repository as upstream

git remote add upstream https://github.com/original-owner/project-name.git

Sync your fork later

git fetch upstream
git merge upstream/main

Troubleshooting

Fork is out of date

Fetch changes from the upstream repository and merge or rebase them into your branch.

Pull request points to the wrong branch

Check that you pushed to the correct branch in your fork before opening the pull request.

Confusing fork and clone

A fork lives on GitHub; a clone is a local copy on your computer.
