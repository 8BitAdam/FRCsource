Intro to GitHub Merges

Topic: Branches and merging · Level: Beginner

Introduction

A merge is what happens when you combine changes from one branch into another. On GitHub, merges are commonly used after a feature branch has been reviewed and is ready to be added into the main branch.

Merging helps teams work on separate features at the same time without overwriting each other’s work.

What is a Merge?

A merge takes the commits from one branch and integrates them into another branch. If the branches share the same history, Git can merge cleanly. If both branches changed the same lines, you may need to resolve conflicts.

Merge Types

Fast-forward merge

Git simply moves the branch pointer forward when no diverging history exists.

Three-way merge

Git creates a new merge commit that combines the two branch histories.

Basic Workflow

  1. Create a feature branch.
  2. Make your changes and commit them.
  3. Open a pull request on GitHub.
  4. Review and approve the changes.
  5. Merge the branch into the main branch.

Examples

Merging a branch locally

git checkout main
git merge feature-branch

Resolving a merge conflict

# fix the conflicting files
git add .
git commit

Troubleshooting

Merge conflicts

Open the files, decide which changes to keep, then stage and commit the resolved version.

Wrong branch merged

Use git branch and git status before merging to confirm you are on the correct branch.
